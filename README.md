## 一、项目背景与痛点解决

Telegram Drive 是基于 Telegram 官方 API 实现的优秀桌面网盘客户端。然而在日常使用中，用户常常遇到以下痛点：
1. **开机死循环下载弹窗**：因下载中断或意外关机，SQLite 数据库 `transfers.db` 记录未正常标记，导致每次开机强制弹出 1.42GB 视频下载窗口，且只能暂停无法取消，重试按钮不断死循环。
2. **频发断流与丢包**：国内通过代理使用时，缺少保活心跳包导致空闲连接被静默掐断（Socket Drop）；默认多并发大文件上传造成 Telegram 官方防刷限速（FLOOD_WAIT）与丢包。
3. **残留硬编码英文说明**：官方只将浅层文本放入 `zh-CN.json`，而将 WebDAV/REST 机制、保险库恢复演练（Vault Drill）、主题说明等硬编码死在 React JS 组件中。
4. **开机 $5 赞助弹窗强制阻拦**：每次启动或完成任务后强弹赞助对话框。
5. **升级后汉化失效**：官方一旦更新，所有修改被覆盖回英文原版。

**Telegram Drive 神行管家** 应运而生，作为专属伴侣工具，一键解决上述所有问题。

## 三、黄金网络参数深度解析

1. **30 秒心跳保活 (`keepAliveIntervalSec: 30`)**：
   电报服务器对代理闲置 TCP 连接敏感。30秒轻量 Ping 保持通道长开，杜绝大文件传输中途被静默掐断。
2. **最大上传并发为 1 (`maxConcurrentUploads: 1`)**：
   单任务独占上传是大文件稳定传输黄金准则。多并发大文件会导致代理拥堵与电报 `FLOOD_WAIT` 惩罚。
3. **4 倍超时容限 (`timeout_multiplier: 4`)**：
   针对跨境代理网络抖动，提供宽限等待时间，不再瞬间判死报错。
4. **512 KB 最佳分块 (`chunk_size_kb: 512`)**：
   最契合电报 MTProto 传输协议的 MTU 尺寸，兼顾吞吐量与抗抖动能力。
5. **5 次失败自愈重试 (`retry_attempts: 5`)**：
   偶发闪断时在后台以指数退避自动重试，无需人工干预重新上传。
